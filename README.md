# babyreel: 개인 육아 영상 자동 편집·배포 파이프라인 (공개 사본)

> **열람 전용 저장소입니다.** 포트폴리오로 코드를 보여 드리려고 공개한 사본으로, 사용·복제·배포·수정을 허락하지 않습니다 (All rights reserved, [LICENSE](LICENSE)).
> 채널·가족 정보와 설정·에셋·프롬프트·문서는 빠져 있어 **이 저장소만으로는 실행되지 않습니다.**

직접 촬영한 가족 영상을 넣어 두면 편집 기획부터 업로드 준비, 업로드 뒤 성과 수집까지 이어서 처리하는 개인 육아 영상 채널용 파이프라인입니다. Python 표준 라이브러리 중심으로 짰고, 이미지·얼굴 처리는 macOS 내장 프레임워크(Swift), 편집은 FilmCraft 편집기를 MCP로 원격 조작합니다.

Claude Code와 함께 설계하고 구현했습니다.

## 흐름

```
촬영 폴더(inbox) ─▶ 정리·컨택트시트·받아쓰기 ─▶ 편집 기획(plan.json) ─▶ 검증
                                                    │
     ┌──────────────────────────────────────────────┘
     ▼
FilmCraft 자동 빌드 (MCP) ─▶ QA (규격·음량·자막 겹침·얼굴 잘림) ─▶ 썸네일
     │
     ▼
메타데이터·일정 ─▶ 배포 (YouTube 비공개 업로드 / 플랫폼별 업로드 폴더) ─▶ 성과 수집·분석
```

1. **수집**: 촬영 폴더의 영상·사진을 날짜별 라이브러리로 옮기고, 중복을 걸러 내고, 컨택트시트와 대사 받아쓰기(로컬 Whisper)를 만듭니다.
2. **기획**: 한 번에 쇼츠 2편과 롱폼 1편을 만드는 편집 기획서(`plan.json`)를 씁니다. 무인 실행 때는 Claude Code를 헤드리스(`claude -p`)로 부르고, 쓸 수 있는 도구를 파이프라인 명령과 파일 편집으로만 제한합니다.
3. **검증**: 기획서 스키마와 편집 규칙(클립 구간, 자막 길이·읽기 시간, 효과 밀도, 음악 전환, 개인정보 노출)을 빌드 전에 점검합니다.
4. **빌드**: FilmCraft를 MCP(stdio)로 띄워 타임라인을 조립하고 쇼츠(1080x1920)·롱폼(1920x1080)·썸네일을 내보냅니다.
5. **QA**: 결과 파일의 해상도·fps·코덱·길이·용량, 라우드니스, 화면 글자 겹침·잘림, 얼굴 잘림을 검사합니다.
6. **배포**: 업로드 일정(쇼츠 매일, 롱폼 이틀에 한 번)을 잡고 플랫폼별 메타데이터를 만든 뒤 YouTube API로 비공개 업로드하거나, 직접 올릴 수 있게 날짜순 업로드 폴더를 준비합니다.
7. **성과**: 채널 공개 페이지와 YouTube Data/Analytics API에서 공개 상태·조회수·시청 지속 곡선을 모아 다음 기획에 쓸 보고서를 만듭니다.

이 과정은 macOS LaunchAgent(새 파일 감시와 정해진 시각)와 텔레그램 봇(제작 요청, 결과·알림 받기)으로 돌아갑니다.

## 기술적으로 집중한 문제

- **편집기 자동 조작**: GUI 편집기를 MCP 서버로 띄워 한 세션 안에서 명령 결과(아이템·클립 id)를 다음 명령에 넘기며 타임라인을 조립합니다. 결과 프로젝트 파일을 편집기에서 열어 사람이 마저 다듬을 수 있습니다.
- **선언형 편집 기획서**: 자막·효과음·스티커·펀치줌 시각을 각 클립 기준 상대 시간으로 적어서, 클립 순서나 구간을 바꿔도 다시 계산할 필요가 없게 했습니다. 쇼츠 2부는 같은 기획서를 "1부처럼 보는" 보기(`Plan.part`)로 만들어 빌더·검증기·메타데이터 코드를 그대로 다시 씁니다.
- **라우드니스 직접 측정**: ffmpeg 없이 결과 오디오를 WAV로 뽑아 ITU-R BS.1770-4 방식(K-weighting 필터, 400ms 블록, 절대/상대 게이트)을 순수 파이썬으로 구현해 통합 음량을 잽니다.
- **아이 개인정보 보호를 검증 단계에서**: 부모 외 인물 얼굴 흐림 누락, 창밖 풍경(Vision 장면 분류로 화면 3x3 칸 판정), 이름표·병원명 같은 글자를 확대 보정이 다시 드러내는지, 아이 실명 노출, 목욕 장면 가림 누락을 빌드 전에 경고하거나 막습니다.
- **얼굴 보존 구도 보정**: 확대·크롭·펀치줌 때문에 얼굴이 화면 밖으로 잘리지 않게, 계획한 구도에서 이미 보이던 얼굴만 지키도록 위치를 옮기고 그래도 안 되면 확대를 줄입니다. 일부러 화면 밖으로 뺀 얼굴은 다시 끌어들이지 않습니다.
- **필요한 클립만 흔들림 보정**: 구간을 저해상도로 내보내 프레임 사이 이동량(위상 상관)을 재고, 기준을 넘는 클립에만 보정을 겁니다. 가림·흐림 영역이 있는 클립은 위치가 어긋날 수 있어 보정하지 않습니다.
- **한국어 TTS 품질**: 숫자·단위를 고유어/한자어로 구분해 읽는 말로 바꾸고, 합성 결과를 다시 받아써 문자 오류율(CER)이 높으면 다시 만들어 가장 나은 결과를 씁니다. 본인 목소리 복제는 채널 주인 목소리로만 허용합니다.
- **끊기기 쉬운 외장 디스크 다루기**: 복사는 항상 `.part`로 쓰고 fsync한 뒤 다시 읽어 해시를 비교하고 나서 이름을 바꿉니다. 원본은 검증이 끝난 뒤에만 지우고, 작업 중에는 잠자기를 막으며, 디스크가 빠지면 아무것도 바꾸지 않고 멈춥니다.
- **업로드 일정과 실제 공개의 동기화**: 채널 공개 페이지에서 읽은 영상을 기록된 영상 id 먼저, 그다음 제목 유사도(difflib)로 회차에 짝짓고, 실제 공개일에 맞춰 남은 일정을 다시 잡습니다.
- **성과를 편집 패턴에 연결**: 시청 지속 곡선의 이탈 지점을 빌드 결과의 구간 정보와 맞춰 어떤 편집 장치(대사·음소거·효과 수·컷 길이)가 있던 구간인지 묶어 봅니다. 수치가 확정되기 전(공개 3일 미만)인 영상과 표본 수가 적을 때는 결론에 쓰지 않습니다.
- **무인 실행 안전장치**: 실행 잠금, 동기화 중인 파일을 건드리지 않도록 촬영 폴더가 안정될 때까지 기다리기, 하루 한 번만 도는 단계 표시, 자동 실행 중에는 브라우저 로그인을 띄우지 않기, 사람이 결과를 확인하기 전에는 바로 공개하는 업로더가 동작하지 않게 막기.

## 테스트

- `tests/test_unit.py`: 단위 테스트 122개 (테스트 클래스 32개). 기획서 검증, 메타데이터, 일정, 성과 분석, 저장소 안전 복사, TTS 텍스트 처리, 챌린지 안전 규칙 등. 외부 서비스는 mock으로 대신합니다.
- `scripts/selftest.py`: 테스트 영상으로 실제 편집기·TTS·받아쓰기를 돌려 명령 전체를 점검하고, 끝나면 테스트 흔적을 지웁니다.

공개 사본에는 채널 설정과 테스트용 기획서·영상이 없어서 이 저장소에서는 테스트가 그대로 통과하지 않습니다.

## 공개 사본 안내

- 채널·가족 정보(이름, 채널 이름·핸들, 목소리·얼굴 기준 데이터)는 중립적인 이름과 자리표시자로 바꿨습니다.
- 설정(`config/`), 에셋(음악·스티커·폰트·사진), 프롬프트(`prompts/`), 문서(`docs/`), 작업 데이터, 비밀 키는 넣지 않았습니다. 코드 안의 `docs/…` 참조는 공개 사본에 없는 비공개 문서를 가리킵니다.
- 채널 기획 규칙, 콘텐츠 문구, 성과 수치 같은 운영 노하우는 자리표시자로 바꾸거나 지웠습니다. 남은 것은 엔지니어링 부분입니다.
- 이 저장소만으로는 실행되지 않으며, 설치·실행 방법은 안내하지 않습니다.
